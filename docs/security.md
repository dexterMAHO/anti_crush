# دسترسی و نگهداری

ناشناس‌بودن عمومی است. اطلاعات دریافتی به درخواست مالک سرویس بدون حذف خودکار
نگهداری می‌شوند. پیام‌های قبل از پذیرش هم در inbox ثبت می‌شوند؛ پذیرش برای
ورود به چرخه انتشار الزامی است. متن قوانین این نگهداری تعاملات را توضیح می‌دهد.

دکمه یا کد پیگیری مجوز نیست. شناسه actor از Telegram Update می‌آید؛ در هر Use Case
نقش از دیتابیس خوانده می‌شود. کاربران عادی فقط وضعیت پیام‌های خود را می‌بینند.
پروفایل و ID فرستنده تنها از /identity و برای OWNER قابل بازیابی هستند؛ درخواست
دارای دلیل و audit است. مدیران زیرساخت و دارندگان backup نیز به داده دسترسی دارند.

توکن و رمزها Environment هستند؛ لاگ عملیاتی فقط نوع خطا را ثبت می‌کند.
SQLAlchemy echo و لاگ HTTP خام فعال نیست. Backup با age رمزگذاری می‌شود.
رمزگذاری دیسک/volume و محل پشتیبان مسئولیت استقرار است؛ بانک داده خودش
رمزگذاری سطح ستون ندارد.

قواعد محلی نشانه‌های اولیه را تشخیص می‌دهند و تضمین تشخیص همه تخلفات نیستند.
AI فقط نتیجه ساختاریافته می‌دهد و هیچ ابزار اجرایی یا مجوز انتشار ندارد.
ناشناس‌بودن متن به‌تنهایی تضمین نمی‌شود؛ نویسنده ممکن است خودش را داخل متن معرفی
کند. مسئول بررسی انسانی باید این موارد را پیش از تأیید کنترل کند.
